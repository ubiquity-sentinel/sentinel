## 1. Principles

1. **Facts over flags.** A decision is a pure function of current GitHub facts plus the immutable ledger (reservations, receipts, release requests). No rule infers meaning from how long a wait lasts. A wait's `reason`, a record's intent and the target's tip health are the inputs.
2. **Every non-terminal state has an exit with exactly one executor.** It is either runnable now, waiting on a named fact with a bound, or parked for the owner with the material and fact-based exits published. An exit table test fails the build for any state that no executor accepts.
3. **Holds require progress.** A record may delay another only while it can itself move during this run.
4. **CI start is a fact, not a result.** A job that never started (no runner, no steps) is neither green nor red. It never charges, never attributes red to a base and never files base repair. Backup CI stands in only for exactly such checks and never overrides a check that ran.
5. **Tested-tip identity.** The default-branch tip only ever moves to a commit whose exact tree passed the target's complete current CI. Train landing is a fast-forward-only ref update, never the merge API. The direct merge-API path re-reads the tip immediately before merging and checks parents afterwards, and is kept only where trains are off. D3 stays off.
6. **Reviews bind bytes, and heads are never rewritten for delivery.** A train member lands its literal reviewed head. A base move alone spends no review round, refresh, CI fix or model start.
7. **Batch by default, bisect on red.** All ready, path-disjoint members of a target ride one train with one CI run. A red train is bisected by prefix in O(log k) runs, and every prefix that lands is itself tested.
8. **Level-triggered and self-certifying.** Train identity is a digest of its manifest, and every stage of a train can be observed on GitHub (ref, PR or dispatch, checks, tip). No new state collection is added; any pass can re-derive everything.
9. **One trusted writer per surface, writes batched.** Launcher phases continue after a write. Bookings are batched. Later, runtime writes are group-committed partitioned by repository.
10. **Capacity comes only from platform and provider facts.** These are the Actions concurrency of the account, the 256-job matrix, rate-limit headers and gateway 429s. Remaining artificial throttles are removed.
11. **Compatible first.** Stages 1–3 add no stored shape. New artifact contracts are introduced reader-first. Every write parses under the recorded rollback runtime.
12. **No silent park.** Every owner park is published once on its issue, with exits based on facts: issue closed, `sentinel:retry` label, or issue body changed.

## 2. Target architecture

```
supervisor run (every ~5–10 min, serialized):
 maintenance (launcher, trusted, per-target tokens)
   queue custody → closure-delivery → retry → TRAIN → delivery(legacy/self) → closure
   (every phase continues after its write; records touched this pass are skipped by later phases)
   state-free passes: base-repair (started-failure only), backup-CI (mirror), outage/owner digest,
                      follow-ups, self-observation
 prepare → matrix_plan (fair-share, batched admission) → matrix_cell (impl/correct/resolve; later review)
 repair (runtime): targets concurrently (S4), per-target serial loop; train targets: no merge, no refresh
                   unless ejected; group-committed writes (S4)
 finalize: run summary incl. disposition counts and wedges ("degraded" when any)
```

Actors and authority:
- **Runtime:** publish, CI-first gating, review requests, refresh (legacy or ejected), CI fix and conflict routing, self merge (`executeSelfMerge`).
- **Launcher:** train build, train CI requests, landing, batched booking, closure, owner publication, backup CI, retirement.
- **Cells:** implementation, correction and conflict resolution. Native review cells come in S5.
- **Release controller:** unchanged; `sentinel-release` stays disabled.

The delivery model per target, when trains are on:
1. Admissible = each reviewed record whose current head has a clean authorizing receipt and CI that is not red.
2. Order them by PR number, then record id.
3. Overlay their path-disjoint reviewed patches onto tip T as one commit C with parents `[T, H1..Hk]` (an octopus merge, so no intermediate commits exist).
4. Run the target's own CI on C. Use backup CI for never-started jobs.
5. Fast-forward the default branch to C.
6. Book every member in one write.

### C3. Target health, outage gate, unhealthy-tip deferral, holds-require-progress (S1)

### C12. Tested-tip delivery train (S3)

**Contract** (integration owner; new `src/contracts/delivery-train.ts`, registered in `docs/contracts.md`):

```
DeliveryTrainManifestV1 { version:"v1", kind:"delivery_train", repository:{owner,name}, branch,
  base: T, members: [{recordId, pr, head, reviewedBase, receiptId, issueNumber}] (1..63, ordered) }
trainId = sha256hex(canonical(["sentinel-delivery-train-v1", manifest]))
ref: refs/heads/sentinel-train/<trainId>
commit: tree = overlay(T, ⊎R_m), parents = [T, H_1..H_k],
  message = "Sentinel delivery train <id12>\n\nDelivers #a, #b, …\n\nSentinel-Train: <trainId>\n
             Sentinel-Train-Manifest: <base64url canonical manifest>" (no closing keywords)
```

**Admission.**
- `trainMemberGate` (new `ops/hosted-autonomy-train-gates.ts`) is composed from the gates `preMergeGate` already uses, minus base equality and the moved-base reads:
  - `deliveryEligible` / `spentDeliveryAdmissible`;
  - `latestAuthorizingReceipt` or `carriedAuthorizingReceipt` over `readTrustedTask`;
  - opt-out, and no existing production release request;
  - PR open, `headSha == record head`, trusted author, `baseRef == default`;
  - `headIsGreen` (head CI not red, #154 coverage);
  - `spentMergeRefusal` and `protectedPathRefusal`;
  - not queue-protected, with no takeover custody and no intent other than a merge intent bound to `(pr, head)`.
- `preMergeGate` is refactored to call the same extracted gates; the direct path stays byte-identical.

**Overlay proof.** Pure `src/repair/train-overlay.ts`, shared by launcher and runtime:
1. For each member in order, compute `R_m = mergeBaseTreeChanges(B0_m, H_m)` (the launcher's existing proof in `ops/hosted-autonomy-github-trees.ts`).
2. A member is **included** when all of these hold:
   - every changed path's entry in T equals R_m's old entry (no drift);
   - its paths are disjoint from paths already claimed, and no claimed path is a directory prefix of another;
   - no submodule changes and no protected path.
3. Otherwise:
   - drift: `ejected:drift`;
   - overlap with an earlier member: `deferred:overlap` (it waits for the next train, where it becomes drift and is refreshed);
   - unreadable: `deferred:facts`.
4. Landing verification: `treeChanges(T, C) === ⊎R_m` exactly, as `(path, oldMode, oldBlob, newMode, newBlob)` tuples. It also checks that C's parents are `[T, H…]` and that the manifest recomputes to `trainId`.

**Build** (launcher, Git Data API only, no local git; `ops/hosted-autonomy-train-build.ts`):
1. `POST /git/trees` with `base_tree` = tree(T) and the member entries (`sha:null` for deletions).
2. `POST /git/commits` with parents `[T, H…]`.
3. `POST /git/refs` for `refs/heads/sentinel-train/<trainId>`. A 422 means the ref exists: read it and verify it.

Idempotency comes from the digest-named ref, not from SHA determinism.

**Active train.** `selectActiveTrainV1` (pure, `src/repair/train-plan.ts`) chooses among existing `sentinel-train/*` refs with base T (`GET /git/matching-refs`) whose members are all still admissible. It takes the one with the most members, with ties broken by the smallest trainId. Members that arrive while a train is in flight wait for the next train. If any member becomes inadmissible, the train is void: its ref is deleted and a new train is built.

**CI** (`ops/hosted-autonomy-train-ci.ts`; `trainCiPolicyV1(repository)` in `src/host/target-policy.ts`):
- Passport: an App-authored train PR (head `sentinel-train/<id>`, base `main`, body = manifest summary, never `Resolves`), giving `pull_request` CI. Never-started jobs go to C7 backup on the subject `(T, C)`.
- ai.ubq.fi: a `train` request kind in `src/host/actions-premerge-ci.ts` dispatches `deno-deploy.yml` on ref `sentinel-train/<id>` with `scope_base=T`, `base_ref`, and `sentinel_pr_author=App` (the complete set). A dispatch is suppressed when a run is already bound to C.
- Parked bot runs are approved as the delivery pass does today.
- Tree identity: for `k=1` where `H` descends from `T`, tree(C) equals tree(H), and the head's own complete green CI counts. No new CI is needed.
- Tested-tree argument: tips only move forward and landing requires `tip == T`. So the pull_request test merge base was T for the whole interval and its tree equals tree(C). `pull_requests[0].base.sha == T` is also checked when it is present.
- Evidence also requires `missingExpectedChecks(C, T)` to be empty, so that late-created `needs:` jobs are covered.

**Bisection** (pure `src/repair/train-bisect.ts`):
- A red train gets one rerun of its failed jobs.
- Base attribution comes first: if the same checks are red on T, the train waits and nobody is evicted.
- Otherwise, up to 3 prefix probes `M[:j]` are spread evenly, each its own digest-named train with its own CI. The longest green prefix lands, which is progress.
- A red singleton `(T, [m])` ejects `m`.
- Pending for 6 h re-requests CI without blame (same trainId).
- This is level-triggered: each pass recomputes the decision from refs and checks.

**Landing** (`ops/hosted-autonomy-train-land.ts`):
1. Re-run `trainMemberGate` for every member, including the final task re-read and opt-out.
2. Re-verify the overlay and the evidence.
3. Read the tip uncached; it must equal T.
4. `PATCH /git/refs/heads/<branch> {sha: C, force: false}`; GitHub refuses a non-fast-forward.
5. Read the tip back.
6. Outcomes:
   - 422 (non-fast-forward): the train is abandoned with `base_moved` and rebuilt next pass;
   - 403/422 for a protected branch: the target's train mode is reported `landing_refused` and the target falls back to the legacy path, never to a racing merge API;
   - a lost response: the next pass decides from the tip (C is the tip or an ancestor of it means landed).

**Booking and settlement.**
- `ops/hosted-autonomy-delivery-proof.ts` gains `HostedDeliveryProof.kind:"train"` through `resolveTrainDelivery`.
- All landed members are booked in one C11 batch write. Release requests use `revision = C`, `head = H_i`, `base = B0_i`; gateway binding uses `gatewayRequestBindsDelivery(…, C)`.
- `intentClosable` (`ops/hosted-autonomy-retries.ts`) clears a merge intent only when `kind == merge`, `pr == member pr` and `expectedHead == H_i`.
- A member PR still open one pass after landing is closed by the App with the comment "Delivered in <C> (Sentinel delivery train <id12>)"; the closure pass accepts the train proof.
- Refs for obsolete trains and probes (base not equal to the tip) are deleted after booking.

**Runtime handoff.** New `src/repair/loop-train-handoff.ts`, `trainHandoff(deps, context, record)`, called at the top of `reconcileMergeIntent` and `executeMerge` for targets where `deliveryTrainModeV1(repo) == "on"`:
- A record that is admissible by the shared static predicate defers with no write: `delivery train: <trainId|pending>`.
- Otherwise the legacy refresh path runs (refresh only; **the runtime never merges on a train target**), when any ejection fact holds:
  - drift: new `src/github/git-train-drift.ts`, `git ls-tree T -- <R_m paths>` against R_m's old entries;
  - singleton red: computed `trainId(T,[m])`, then `readRef`, then CI;
  - a protected path or submodule.
- An unhealthy tip defers everything (C3).
- `verifyTrainLandingV1` (`src/repair/train-proof.ts`) lets C1's booking rule recognize train-merged PRs. The runtime defers them to launcher booking (`train_booking_pending`). W5 flags booking that has not happened after 2 passes.

**Enablement.**
- `deliveryTrainModeV1(repository)` in `src/host/target-policy.ts` returns `"off" | "plan_only" | "on"` and is read by both sides. Being a code constant means auto-follow installs it with no workflow change.
- A new runner phase `train` runs after `retry` and before `delivery`, continues after its write, and writes its journal to GitHub only.

**Activation gate.** Probes P1–P5 (§9) must pass. The integration owner records "tested-tip delivery train" in `docs/DECISIONS.md`: members land their literal current-head-reviewed heads, the tip is a CI-tested tree, and D3 stays off. An independent read-only audit by a fresh GPT-6.1 Sol/max agent is required before `on`.

**Migration.** The 22 Passport merge intents become members once the base is healthy; receipts and reservations are untouched. Self keeps `executeSelfMerge` (k=1).

**Tests.**
- `tests/repair/train-overlay_test.ts`: drift, overlap, directory prefix, deletion, mode-only, binary, protected, submodule.
- `tests/repair/train-plan_test.ts`: active-train selection is deterministic and ignores time and list order.
- `tests/repair/train-bisect_test.ts`: k=22 with the culprit at 9: prefix 8 lands, 9 is ejected, 10–22 form the next train; at most 3 probes per round; flaky green on rerun; base red evicts nobody.
- `tests/host/train-land_test.ts`: temporary bare remote plus fake GitHub; a tip moved before the PATCH is refused with nothing booked; a lost response is adopted; every new tip tree equals the tested tree.

## 6. Invariants checklist

- [ ] **Native review mode only** (`review/start`, `codex review`, `codex exec review`; Codex chooses the reviewer). No stage selects a model or copies a rubric, and the rubric constant is untouched. S5 review cells keep the `enteredReviewMode`/`exitedReviewMode` binding.
- [ ] **A merge needs a completed current-head receipt with no unresolved P0** (P1–P3 never block). Train members land their literal reviewed heads, and carried receipts apply only where option (b) already allows them.
- [ ] **Current-head CI not red** on each member head, **and** complete green CI on the landed tree. Backup evidence counts only for never-started checks and never overrides a check that ran and failed. Missing, stale or unverifiable evidence never passes.
- [ ] **The merged tree is never one no CI ran on:**
  - C1 closes the runtime race;
  - trains land by fast-forward to a tested commit (an octopus, so there are no intermediate commits);
  - D3 stays `false`;
  - release requests name the tested tip.
- [ ] **No branch protection rules or rulesets are ever added.** A target that refuses the ref update falls back to legacy instead.
- [ ] **Model workers get no credentials, state writes, admission or promotion authority.** Trains, backup CI, landing and booking belong to the launcher. The backup mirror has no secrets.
- [ ] **A durable reservation precedes every model or review start.** Batched admission keeps write-before-start. Ambiguous starts stay charged; there are no refunds.
- [ ] **Custody and exact accounting.** Intent before effect, or reconcile-by-observation for idempotent digest-named effects. Done rows are immutable and no record is dropped (`validateRepairTransition`).
- [ ] **Compatible historical readers.** S1–S3 add no stored shape. The validator allowlist applies to new writes only. New artifact contracts are reader-first. Rollback runtimes parse every write.
- [ ] **`sentinel-release` stays disabled.** Release-deferred rows are counted, never reported as delivered.
- [ ] **Artificial caps lifted.** The last correction throttle goes. Only platform and provider limits bound the system: Actions concurrency, the 256-job matrix, rate limits, 429s and the 63-parent manifest parser bound.
- [ ] **Queue proof off, outside-contributor PRs ignored.** Only App-authored `sentinel/repair/*` PRs are members or closed.
- [ ] **The owner hand-lands protected files.** Protected candidates are never pushed to a branch. Diffs are published to the owner on the source repository.
- [ ] **Five review rounds** for CI-first-era records, three for legacy ones. Base moves spend no round in the train.
- [ ] **Self target unchanged** (`executeSelfMerge`, native CI). Auto-follow default and workflow-change deferral unchanged.
- [ ] **Development rules:** only sanitized minimal fixtures; 300 s command bounds; no whole-repository sweeps; file size ceilings (new code goes in new files, because `git-executor.ts` is at 974 lines, `spent-delivery.ts` at 945, `retries.ts` at 955 and `delivery-pass.ts` at 887).
